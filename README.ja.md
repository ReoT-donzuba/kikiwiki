# 聞き書きWiki（KikiWiki）

**[English](README.md) | 日本語**

会話から自分の経験知を引き出し、出所を辿れる形で蓄積していくナレッジ基盤です。

> **聞いて、書いて、辿れる形にする。**

これは**空の状態のスターターキット**です。中身（ノート）はゼロ件で、書き方の見本としてサンプルノート1件だけ入っています。

> **先に雰囲気を知りたい人へ：** [EXAMPLE-CONVERSATION.md](EXAMPLE-CONVERSATION.md) に、そのサンプルノート1件ができるまでの会話を全文載せています。どれくらい雑に話せばノートになるのかが、説明を読むより早く分かります。

## 名前について

「聞き書き」は、民俗学や地域史で使われる「本人に聞いて、本人の言葉で書き残す」技法の名前です。この仕組みの入力源が外部記事ではなく**人への聞き取り**であることを指しています。そこから体系化層（`wiki/`）へ統合するので、`聞き書き` + `Wiki` = **聞き書きWiki**、略称 **KikiWiki** としています。

（略称は初出のあとで使ってください。`Kiki` 単体では「聞き」の意味が立たないため使いません。）

## これは何か

ノウハウを残す作業は本来重い。書く時間がない、書いても探せない、探せないから誰も書かない ── という順番で形骸化します。

この仕組みは、**整形と構造化をAIに任せ、人間は話すだけ**にすることでその重さを外します。あなたはAIエージェントに起きた出来事をそのまま話す。AIがテンプレートに沿ってノートへ落とし、タグを付け、カタログを更新する。人間がやるのは事実確認だけです。

Andrej Karpathyの [LLM Wiki パターン](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) を出発点にしていますが、次の3点を変えています。

| Karpathy原案 | 聞き書きWiki |
|---|---|
| 外部ソース（記事・論文等）をLLMが取り込む | **会話・インタビューで人の暗黙知を引き出す** |
| LLMがWikiの主要な書き手 | **LLMは整形役**。`knowledge_origin` / `evidence_level` で出所と確度を記録し、事実確認は人が行う |
| index.md / log.md でフラットに管理 | **raw層（`notes/`・追記のみ）と wiki層（`wiki/`・上書き正本）の2層** |

## 必要なもの

| | 必須か | 備考 |
|---|---|---|
| VSCode | 必須 | 拡張機能でAIエージェントを動かします |
| AIエージェント（下記いずれか1つ） | 必須 | Claude Code 拡張 または GitHub Copilot Chat |
| Git | 任意 | なくても動きます（[後述](#git-がない端末の場合)） |
| Python / Node.js などのランタイム | **不要** | 中身はMarkdownファイルだけです |

指示ファイルは主要ツール向けに同梱済みで、リポジトリを開くだけで自動的に読み込まれます。

| ツール | 自動で読み込まれる指示ファイル |
|---|---|
| Claude Code | `CLAUDE.md` |
| GitHub Copilot Chat | `.github/copilot-instructions.md` |
| Codex など汎用エージェント | `AGENTS.md` |

3つとも共通ルール `wiki-config/ai-agent-rules.md` を参照する構成です。**ルールを変えるときは共通ルール側を直せば全ツールに効きます。**

## 導入方法

### 1. ファイルを配置する

このリポジトリの中身を、新しいフォルダのルートに置きます。`README.md` や `wiki-config/` がフォルダの直下に来る形にしてください。`.github` と `.claude` は先頭がドットの隠しフォルダなので、コピー漏れに注意してください。

GitHubから取得する場合は、次のどちらかです。

```bash
# A. 自分のWikiとして使う（このリポジトリの履歴は引き継がない）
git clone --depth 1 https://github.com/ReoT-donzuba/kikiwiki.git my-wiki
cd my-wiki
rm -rf .git
git init && git add -A && git commit -m "init: 聞き書きWiki を導入"
```

```bash
# B. 改善をこのリポジトリへ還元したい（履歴ごと取得）
git clone https://github.com/ReoT-donzuba/kikiwiki.git
```

**基本はAです。** あなたのノートはあなたのものなので、このリポジトリの履歴とは切り離してください。

#### Git がない端末の場合

Gitは必須ではありません。**ZIPでダウンロードしてフォルダをそのまま使えば動きます。** ノートの追加も検索もAIエージェントがファイルを直接読み書きするだけなので、Gitがなくても機能は落ちません。

失うのは変更履歴です。次のどちらかで代替してください。

- **`notes/log.md` を履歴の代わりにする。** もともと「いつ何を追加・更新したか」を記録するファイルです。Gitがない場合はここが唯一の履歴になるので、AIに毎回追記させてください（同梱の指示ファイルにその動作が入っています）。
- **フォルダを定期的に複製して残す。** OneDriveなどの同期フォルダに置けば、バージョン履歴機能で世代管理できる場合があります。

あとからGitを導入しても問題ありません。その時点で `git init` すれば、それ以降の履歴が残ります。

### 2. AIエージェントを用意する

どちらか片方でよいです。両方入れて使い分けてもかまいません。

#### A. VSCode + Claude Code 拡張

1. VSCode の拡張機能ビュー（`Ctrl+Shift+X`）で **Claude Code** を検索し、インストールする。
2. サイドバーの Claude アイコンからパネルを開き、サインインする。**Claude の有料プラン（Pro / Max / Team）またはAPIキーが必要**なので、自分が使える契約があるか事前に確認してください。
3. 手順1で作ったフォルダを VSCode で開く（`ファイル > フォルダーを開く`）。ルートの `CLAUDE.md` が自動的に読み込まれます。
4. スラッシュコマンド（`/knowledge-add-interview` など）は追加設定なしで使えます。チャットに `/` を入力すると候補が出ます。

#### B. GitHub Copilot Chat

1. VSCode の拡張機能ビューで **GitHub Copilot** と **GitHub Copilot Chat** をインストールする。
2. GitHubアカウントでサインインする。**Copilotのライセンスが割り当てられている必要があります。**
3. 手順1で作ったフォルダを VSCode で開く。`.github/copilot-instructions.md` が自動的に読み込まれます。
4. `.github/prompts/` の定型プロンプトを `/` から呼び出すには、VSCodeの設定で**プロンプトファイル機能を有効化**します。設定検索（`Ctrl+,`）で `prompt files` を探して有効にしてください。設定名はVSCodeのバージョンで変わることがあります。

### 3. 動作確認をする

チャットに次を投げて、指示ファイルが読まれているかを確かめます。

```
このWikiのルールを要約して。ノートを書くときのメタデータ項目を挙げて。
```

`knowledge_origin` と `evidence_level` が挙がれば、共通ルールまで読めています。出てこない場合は、フォルダのルートを開いているか（`wiki-config/` の親ではなく `wiki-config/` があるフォルダを開いているか）を確認してください。

### 4. 最初のノートを1件書く
今日困ったことを、整形せずそのまま話すだけでよいです。

```
今日 Docker のボリューム権限エラーが出て、こう解決した。ノートにして。
```

話す材料がまとまっていないときは、AIに質問させます。

```
インタビュー形式で知識追加して
```

質問は1つずつ来るので、短く答えるだけで1件のノートになります。

**どれくらい雑に話してよいのか**が分からないときは、[EXAMPLE-CONVERSATION.md](EXAMPLE-CONVERSATION.md) を先に読んでください。同梱のサンプルノート1件が、実際どんな会話から作られたかを全部載せています。「エラー文はもう残ってない」で通ることが分かると思います。

自分のノートが1件書けたら、サンプルノート `notes/20260513-docker-recover-volume-linux.md` は削除してかまいません。

## 日々の使い方

新しいセッションを始めるときは、まず現状を読ませます。前回どこまでやったかを毎回説明しなくて済みます。

```
notes/log.md と notes/index.md を読んで、このWikiの現状を把握して
```

あとは目的に応じて話しかけるだけです。

| やりたいこと | 言い方 |
|---|---|
| 知識を追加する | `インタビュー形式で知識追加して` / 出来事をそのまま話す |
| ノウハウを探す | `〜について、自分の経験だけで検索して`（出所・確度で絞り込める） |
| 健全性を点検する | `Lintして`（矛盾・陳腐化・孤立・昇格待ちを検出） |
| 文章を整える | `このノートを読みやすくして`（`humanize-text` スキル） |

上の3つはスラッシュコマンドでも起動できます。`/knowledge-add-interview`、`/knowledge-search`、`/lint` です。Claude Code と Copilot Chat のどちらでも同じ名前で使えます。**毎回同じ手順を確実に踏ませたいときは、自然文よりこちらが安定します。**

手順の中身は `.github/prompts/` 側が正本です。`.claude/commands/` はそこを参照するだけの薄い入口なので、プロンプトを直すときは `.github/prompts/` を編集してください。

## 構成

**書くときは `notes/`、引くときは `wiki/`。**

| 層 | 場所 | 単位 | 更新 |
|---|---|---|---|
| raw | `notes/` | 1ノート1結論・日付付き | 追記のみ |
| wiki | `wiki/` | 1ページ1テーマ（複数ノートの統合）・日付なし | 上書き |

```
.
├── README.md                  英語版の説明
├── README.ja.md               このファイル
├── EXAMPLE-CONVERSATION.md    サンプル会話（1件のノートができるまで）
├── CLAUDE.md                  Claude Code 用の指示
├── AGENTS.md                  汎用エージェント用の指示
├── .github/
│   ├── copilot-instructions.md    Copilot 用の指示
│   └── prompts/                   定型プロンプト（知識追加・検索・Lint）
├── .claude/
│   ├── commands/                  Claude Code 用スラッシュコマンド（上記prompts参照）
│   └── skills/                    Claude Code 用スキル（humanize-text）
├── wiki-config/
│   ├── ai-agent-rules.md          共通ルール（全ツールがこれを参照）
│   ├── TEMPLATE.md                ノートの標準フォーマット
│   ├── WIKI-TEMPLATE.md           wikiページのフォーマットと書き方ルール
│   ├── tags.md                    タグの管理語彙
│   ├── operations.md              運用・品質管理ルール
│   ├── conversation-workflow.md   会話でノート化する手順
│   └── chat-prompts.md            会話プロンプト例
├── notes/                     raw層。ここに書く
│   ├── index.md                   ノートのカタログ
│   └── log.md                     更新履歴
└── wiki/                      体系化層。ここから引く
    └── README.md                  逆引き表（やりたいこと→参照先）
```

## 運用の原則

形骸化を防ぐために効いているのは、この5つです。

1. **1ノート1結論。** 1つのノートで言えることを1つに絞る。長いノートは読まれず、探されません。
2. **出所と確度を必ず書く。** `knowledge_origin`（自分の経験 / 人から聞いた / 複数から統合）と `evidence_level`（検証済み / 未検証）をメタデータに残す。**これがないと、聞いた話を自分の経験と混同します。**
3. **書くときは notes、引くときは wiki。逆流させない。** wikiの編集でnotesを書き換えない。食い違ったら**ノートが正**で、wikiを直す。
4. **出典を辿れない段落は書かない。** wikiページには出典ノートを必ず列挙する。
5. **未解決を解決済みに見せない。** ノート側で答えが出ていない問いは、wikiの「未確定・次の問い」に落とす。

## 育て方の目安

| ノート数 | やること |
|---|---|
| 〜10件 | `notes/` だけで運用する。wiki層はまだ作らない |
| 10件 | Lintを1回まわす。孤立ノートと書式のブレを潰す |
| 同一テーマ3件 | そのテーマのwikiページを1枚作る |
| 30件 | タグ体系を見直す。`notes/index.md` のカテゴリ分割を検討する |
| 月1回 | Lint実行。テンプレやルール自体の改善もAIに提案させる |

テンプレートやルールは「現在の最善」を反映するもので、固定するものではありません。気づいたら `wiki-config/` を更新してください。過去のノートはLintが少しずつ収束させます。全件見直す必要はありません。

## 注意

- **案件固有情報の扱いを最初に決めてください。** 顧客名・固有の設計判断を含むノートは、他組織へ持ち出せません。`wiki-config/WIKI-TEMPLATE.md` の `portable: yes | no` で持ち出し可否を明示する運用にしています。
- **自分のWikiを公開リポジトリに置かないでください。** ノートには業務上の判断や未検証の推測が入ります。Gitで管理する場合はプライベートリポジトリを使ってください。
- **Windows + PowerShell 5.1 を使う場合**、日本語の文字化け対策として `-Encoding UTF8` の明示が必須です。ルールは `wiki-config/ai-agent-rules.md` に記載済みです。
- AIエージェントによるノート削除や `deprecated` への変更は、確認を取る設定にしています（`wiki-config/ai-agent-rules.md` の「破壊的操作の制限」）。
